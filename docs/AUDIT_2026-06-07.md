## What's solid — do NOT re-litigate
- **Librarian rule is enforced in the CODE, not just tests.** Every emitted string is neutral/count
  based; every `sort`/`max`/`min` keys on a stable field (id, date, key), never on magnitude or
  severity. Interpretive words appear only in docstrings *negating* interpretation.
- **Algorithms sound + deterministic** — Pettitt 1979 pivot (cadence), proper sliding-window
  frequency, deterministic one-to-one greedy co-occurrence (no double-count). Output byte-identical
  across runs.
- **Fail-closed multi-patient identity verified by live probing** — duplicate/ambiguous/missing
  identity always quarantines; never merges or guesses.
- **Compliance/legal framing is the strongest part** — every HIPAA/FDA/de-id claim correctly hedged
  ("Safe-Harbor-*shaped*, not a determination"; "date-shift = Expert Determination NOT Safe Harbor";
  "Non-Device status is a classification, not tort immunity"; RESEARCH_ONLY; not counsel-verified).
  No doc overclaims approval.
- Engine + extractor test coverage is thorough where it matters (all 5 rules have negative/boundary/
  threshold tests; the 4 merge-safety guards and all 4 quarantine reasons are tested).

## Detailed findings

### Engine + extractor (recurrence.py 1334 ln, extract.py 1206 ln)
- **5 rules confirmed:** `detect_recurrence` (:300), `detect_gap` (:396), `detect_frequency` (:463),
  `detect_cooccurrence` (:581), `detect_cadence_change` (:749). Shared matching core `_record_groups`
  so exact/normalize/synonym/fuzzy behave identically across rules.
- **Routing:** `EXPERTS` registry is an ordered tuple; `run_report` iterates in registry order,
  records emitted sorted by id (not by finding count/magnitude). No ranking anywhere.
- **Extractor:** gazetteer/allowlist emits only curated canonicals; 4 merge-safety guards present and
  tested (affix-antonym detector, LASA/look-alike denylist, drug-name fuzzy exemption, gazetteer-
  anchored fuzzy); relative-date anchoring resolves only explicitly-anchored relatives, else stays
  cited-but-undated; `extract_records_multi` fail-closed (quarantine on missing/ambiguous/duplicate
  key or missing shift) — verified by probing. Bad DATA → quarantine; only bad CONFIG raises.
- **De-id posture:** consistent per-record date shift preserves intervals; allowlist limits emitted
  content; record id is the verbatim `Patient:` header (never gazetteer-scanned). Docstrings careful
  not to overclaim de-identification.
- **Quality:** no TODO/FIXME; robust dirty-data handling (None items, missing dates, non-dict
  entries) without crashing; thorough type hints; deterministic. Latent-but-unreachable: a frequency
  formatter that `TypeError`s only if hand-fed a malformed hit; a `casefold()` offset assumption that
  holds for ASCII but not every Unicode (`ß`→`ss`) — never triggers on the synthetic English gazetteer.
